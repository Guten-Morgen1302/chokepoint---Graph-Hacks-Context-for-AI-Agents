## Vision

### 10x Check

Incumbent tools list attack paths. Chokepoint finds the cheapest fix the organisation **can actually ship**, proves the fix cuts every route, and records why each exception exists, all on one live FalkorDB graph.

Some facts that make a cheap fix unshippable only exist in text. The demo example is a DR runbook that says a dormant grant is still needed. The LLM reads that text and proposes constraints with citations. The graph recomputes the fix and proves it.

## Accepted Scope

- **Agent loop (CEO-5):**
  - OBSERVE and BASELINE run on the server, before the LLM.
  - CRITIQUE uses the batched `explain_grant`.
  - At most 3 `what_if` calls, then `choose_plan` with automatic verification, then `draft_tickets`, then ESCALATE.
  - Budget: 12 tool calls and 60 s.
  - Citations must come from evidence returned in the same run.
  - If the agent fails, the deterministic fallback shows P0, labelled "Not reviewed by agent".
- **Moat (CEO-6):** three honest claims, plus the measured maxFlow count shown on screen. Tenancy through `GRAPH.COPY` is the claim specific to FalkorDB. The README includes a rule-3 audit. No speed or exclusivity claims.
- **Cost (CEO-7):** based on usage only. Known breakage is reported as `services_broken`. The demo dependency (the DR failover job: dormant, not registered) appears only in the runbook.
- **Accepted risk (CEO-7b):** requires `review_by` and citations. It keeps capacity at BIG until reviewed. A review is a superseding decision.
- **Tie-break (CEO-8):** candidates are `cut_src` and `cut_sink`. Prefer fewer services broken, then `cut_src`. The agent can override with citations. F-2 has one designed tie.
- **Video (CEO-9):** 7 segments in 3 minutes. The agent's judgment beat gets 50 s.
- **Track 03 (CEO-10):** a knowledge layer built by ingestion, plus `explain_grant`, `who_knows` and policy drift.
- **Tracks (CEO-11):** entering all three.
- **Cut line (CEO-12):** tenancy is the last item.
- **Schedule (CEO-13):** the knowledge text is written in notes before Oct 15. Checkpoint A has a deterministic fallback.
